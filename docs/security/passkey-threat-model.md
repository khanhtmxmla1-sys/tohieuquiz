# Staff passkey threat model

## Scope

Passkeys supplement the existing password login for teacher and administrator accounts. Password login and audited password recovery remain available during the initial rollout. Student and parent accounts are not eligible.

## Trust boundaries

- RP ID is fixed to `thtohieu.com`.
- Production origins are an exact allowlist: `https://thtohieu.com` and `https://www.thtohieu.com`.
- The Worker uses pinned `@simplewebauthn/server` version 13.3.0. The browser uses pinned `@simplewebauthn/browser` version 13.3.0. No custom CBOR, COSE, signature, authenticator-data, or attestation parser is implemented.
- Successful passkey authentication issues the same server-side session record, JWT claims, and HttpOnly cookie as password authentication.

## Challenge controls

- Challenges are cryptographically random values generated by SimpleWebAuthn.
- D1 stores only SHA-256 challenge hashes.
- Challenges expire after five minutes and are scoped by username, role, purpose, and challenge ID.
- Verification compares the presented challenge through the library callback. The challenge is then consumed with a conditional update. Reuse and concurrent replay fail closed.
- Expired challenge rows are purged by the daily security retention job.

## Credential controls

- Credential public key, ID, transports, device type, backup state, signature counter, timestamps, label, and revocation state are stored.
- User verification is required for registration and authentication.
- ES256 and RS256 are the only accepted registration algorithms.
- The library verifies origin, RP ID hash, user-presence/user-verification flags, signature, and counter. A compare-and-swap counter update adds protection against concurrent cloned-authenticator requests.
- Adding and removing a passkey produces a security event with actor and request ID. Full credential IDs, user-agent strings, IP addresses, tokens, and challenges are not placed in audit metadata.

## Recovery and rollback

- Password authentication remains the recovery path in the initial release.
- Password change/reset and session revocation continue to be audited by Security Center.
- Removing a passkey requires an authenticated staff session. Existing sessions can be revoked separately.
- Rollback disables passkey UI/routes or removes migration `0053`; password authentication remains available throughout.

## Abuse cases covered

- Reused or expired challenge.
- Wrong origin or RP ID.
- Missing user verification.
- Credential belonging to another staff account.
- Revoked credential.
- Signature counter replay or cloned authenticator.
- Public endpoint brute force, mitigated by the same fail-closed login rate limit as password login.
